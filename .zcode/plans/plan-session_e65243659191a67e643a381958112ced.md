# Combat Power stat + usage-based skill XP + unified combat loop

(Same plan as reviewed, with the wiki edits removed — `wiki/` stays untouched.)

## Design summary

**Power — one derived, auto-calculated stat, obfuscated from combat code.** Auto-attack damage today is assembled from five scattered places (Lua `base_damage`, `StatComponent.AttackDamage`, weapon scaling fields that are never even parsed, a dead `basePower`, mastery that never updates). Replaced by two derived fields on `StatComponent`, computed in **one place** (`PowerCalculator`); `CombatSystem` only ever reads the finished fields:

```
statBase     = 5 + 2*Strength + 0.5*Dexterity
weaponPower  = (weapon.minDamage + weapon.maxDamage)/2
              + Strength*strScaling + Dexterity*dexScaling + Intelligence*intScaling
             (unarmed: 0 — bare fists run on statBase alone, no punch skill needed)
masteryBonus = 1 + 0.005*(level-1) of the equipped weapon's primary skill, cap +50%
Power        = (statBase + weaponPower) * masteryBonus        // auto-attacks & weapon skills

MagicPower   = 5 + 2*Intelligence + 0.5*Wisdom + MagicDamage   // casts — NOT Power
```

**C++ owns damage.** Lua skills stop hardcoding `base_damage` and return a multiplier (slash 1.2x, stab 0.8x). `ProcessAttack` computes `max(1, round(base * multiplier * variance(0.9-1.1) * critMult) - mitigation)`; base = `Power` (physical) or `MagicPower` (magic damage types), mitigation = `Armour` / `MagicDefense`. Crit unified in C++ for everyone: `chance = min(0.25, 0.05 + 0.001*Dexterity)`, x1.5; Lua `is_critical` still honored via the "critical" tag.

**Renewing combat intents = the auto-attack loop (players AND mobs).** `attack goblin` needs no skill alias: targeting resolves and plants `CombatIntentComponent{attackOnce=false, nextFireTime=now}`. `CombatSystem::run` processes intents when due, then: if `!attackOnce && target alive && same room` → `nextFireTime = now + AttackInterval(source)`; else remove. `stop` clears it. Renewal on combat-speed cadence, never per-tick.

**CombatStateSystem is deleted entirely.** Its four jobs are redistributed:
- *Cadence* → the renewal loop. Mob interval = `MobAttackComponent::attackSpeed`; player interval = weapon `baseWindup` shrunk by stats (existing `CalculateAttackInterval` formula, moved into `PowerCalculator::AttackInterval`).
- *Mob attack flavor* (attack-pattern rolls + Lua `on_attack` boss hooks) → new helper `Utils/MobAttackBuilder::BuildAttack(registry, mobID)` returning `{multiplier, verb, damageType}`, called by CombatSystem each time a mob's renewing intent fires (fresh pattern roll per swing). Kills the mob `attackDamage x attackDamage` double-dip — mob Power comes from the same PowerCalculator over their stats + `attack_damage`.
- *Target validation* (dead / left room / invalid) → CombatSystem renewal conditions; death handler covers the rest.
- *Player branch* → already unreachable dead code; deleted.
- Callers updated: `GameEngine` (de-instantiate/call), `BehaviorSystem` (aggro plants the mob's first renewing intent instead of `CombatStateComponent`; its AI validation loop deleted — subsumed), `StopCommandHandler` (stops renewing intent + windup), `CombatComponents.h` (drop include). `CombatStateComponent.h` deleted.

**Death handling extracted** — killing-blow point is `CombatSystem::ProcessAttack` `Health <= 0` (CombatSystem.cpp:122-141). Extract into `CombatSystem::HandleDeath(sourceID, targetID, intent)`:
- player target → existing defeat message (unchanged)
- mob target → NEW "You have slain X!" message to the killer, `DeadTag` (RespawnSystem unchanged), **kill XP: +50 to the killing skill** (`intent.skillID`, or the weapon's primary skill for auto-attack kills)
- publishes new `EventType::EntityDeath{sourceID, targetID, skillID}`, bridged to Lua as an `EntityDeath` hook (future loot/quest logic subscribes there, never in CombatSystem)

**Usage-based skill XP.** Every successful skill execution (any skill) grants +10 XP and bumps a use counter; killing blows +50. Curve: `xpToNext(level) = 100 * level^1.5`. Level-up sends a `skill_up` GameMessage, publishes `SkillLevelUp` (bridged to Lua), and re-runs PowerCalculator (mastery feeds Power). Progress persists in `players.player_players.state` as `skills: {"slash": {level, xp, uses}, ...}` — keyed by skill template name (entity IDs are runtime-only); loaded back on login.

**Components** (`Include/Components/`)
- `StatComponent.h` — add derived `Power`, `MagicPower`
- `CombatIntentComponent.h` — add `nextFireTime` (double, 0 = due now)
- `SkillHolderComponent.h` — replace `mastery`/`skillUses` maps with `map<int, SkillProgress{level=1, xp, uses}>`; `AddXP()` returning level-up bool; `XPForNext()`
- `SkillDefintionComponent.h` — add `templateID` (stable persistence key)
- DELETE `CombatStateComponent.h`

**New files** (registered in `.vcxproj`, `.vcxproj.filters`, `CMakeLists.txt`)
- `Utils/PowerCalculator.h/.cpp` — `RecalculateDerivedStats`, `AttackInterval`, all tunable constants
- `Utils/MobAttackBuilder.h/.cpp` — pattern roll + Lua `on_attack` invocation (takes over the sol2 usage from CombatStateSystem)
- `Commands/StatsCommandHandler.cpp` — minimal `stats` command: HP/Mana, Power + MagicPower, skills with level/XP bars (registered alongside other commands)

**Systems**
- `CombatSystem.cpp` — due/renew/remove intent loop with room+alive checks; new damage formula; unified crit; `HandleDeath` (kill message, kill XP, DeadTag, `EntityDeath` event); mob intents ask `MobAttackBuilder` for flavor when they fire
- `SkillSystem.cpp` — implement `GrantSkillXP`; +10 XP on `result.success`; `ctx.basePower` = source `Power`; skill-up message/event/recalc
- DELETE `CombatStateSystem.h/.cpp`
- `BehaviorSystem.cpp` — aggro plants first renewing mob intent; delete subsumed AI validation loop
- `TargetingSystem.cpp` — `skillID < 0` → plant basic-attack `CombatIntent` instead of `SkillIntent`
- `CombatCommandHandler.cpp` — `attack` uses basic-attack mode (works bare-handed; weapon skills still castable via `cast`)
- `StopCommandHandler.cpp` — clear renewing `CombatIntentComponent` + windup
- `InventorySystem.cpp` — `RecalculateStats` delegates derived stats to PowerCalculator; unequip no longer rips out the `attack` alias
- `GameEngine.h/.cpp` — remove CombatStateSystem member/instantiation/update call

**Factories / DB / events**
- `ItemFactory.cpp` — actually parse `strScaling/dexScaling/intScaling/baseWindup/scalingStat/scalingFactor/maxRange` from weapon docs (admin edits these today; the server silently drops them)
- `MobFactory.cpp`, `PlayerFactory.cpp` — run PowerCalculator after stat attach; PlayerFactory loads `state.skills`, drops the broken `skill_punch` seeding
- `SkillFactory.cpp` — stamp `templateID`, expose name→entity index
- `PostgresDatabase.cpp` — `SavePlayer` writes `state.skills`
- `EventBus.h` — `EventType::SkillLevelUp` + `EventType::EntityDeath` (+ data structs, variant entries); bridges in `ScriptEventBridge.h`

**Lua** (server restart required — skill scripts don't hot-reload)
- `scripts/skills/melee_helper.lua` — `magnitude` = multiplier, verb from def, drop `base_damage`
- `scripts/skills/Combat/blades.lua` — slash 1.2 / stab 0.8 / poke 1.0
